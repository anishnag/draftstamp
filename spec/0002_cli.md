# draftstamp-cli

Status: Draft · 2026-11-21

The `draftstamp` command. A thin front end over `draftstamp-core`: it parses arguments, opens the vault, supplies native HTTP, and prints plain results. All format and verification rules live in core.

## Commands

```
draftstamp init [--project <name>]              write .draftstamp in this folder
draftstamp stamp [<folder> | <file>] [-m <label>] [--project <name>]
draftstamp upgrade [<stamp>]                    complete pending proofs (all pending if none given)
draftstamp log [--project <name> | --all]       stamps, newest first
draftstamp find <file>                          stamps containing this file's exact bytes
draftstamp check [<stamp>]                      offline: is the stored record intact?
draftstamp verify [<stamp>]                     check, then confirm the date with Bitcoin
draftstamp share <path> [--stamp <stamp>] [-o <dir>]   one file and its .ots
draftstamp export [<stamp>] [-o <file.zip>]     everything, each file with its own .ots
```

Every command takes `--vault <dir>`.

| Command | Network | Writes |
|---|---|---|
| `init` | no | `.draftstamp` (refuses to overwrite) |
| `stamp` | calendars | a new bundle in the vault |
| `upgrade` | calendars, explorers | upgraded proofs in the vault |
| `log`, `find` | no | nothing |
| `check` | no | nothing |
| `verify` | explorers | nothing |
| `share` | calendars, explorers (one upgrade attempt) | `<dir>/<name>` and `<dir>/<name>.ots` |
| `export` | no | one zip |

## Defaults

- **What `stamp` stamps:** the current directory, or the folder or single file given. A single file becomes a one-file stamp whose path is the file's name; `.draftstampignore` does not apply to a file named directly (the format's built-in skip list still does).
- **Project:** `--project`, then `.draftstamp` in the folder (for a file, in the file's folder), then the folder's name (for a file, the file's name). `log` with neither `--project` nor `--all` shows the current folder's project. The tag is recorded in each stamp's receipt (advisory, outside the commitment) and never changed afterwards, so renaming a project leaves earlier stamps under the old name; nothing is rewritten. `stamp --project` tags only that stamp and never edits `.draftstamp`; when it differs from `.draftstamp`, `stamp` prints a note.
- **Vault:** `--vault`, then `$DRAFTSTAMP_VAULT`, then `~/draftstamp`. A visible folder in the home directory, because it holds the user's records and should be easy to find and back up. Created on first stamp.
- **`<stamp>`:** a full stamp id, a unique prefix of one, or its 6-character hex suffix. Omitted, it means the newest stamp of the current folder's project. An ambiguous reference is an error listing the matches.
- **`share <path>`:** `<path>` is the file's path inside the stamp (as `log` and `find` show it, e.g. `chapters/chapter3.tex`). Without `--stamp`, it uses the newest stamp of the current project that contains that path. If the stamp's proof is pending, `share` tries one upgrade first and saves it to the vault, so the shared proof reaches Bitcoin when it can; if still pending, it says so. Output defaults to the current directory. It never overwrites: an existing `.ots` is an error, and an existing file is left in place if identical (sharing from the project folder) and an error otherwise.
- **`export`:** writes `<stamp id>.zip` in the current directory unless `-o` is given; refuses to overwrite.

- **`check`** (offline): re-hashes every file in the stamp's snapshot against the receipt, rebuilds the tree and commitment, and checks `proof.ots` is a proof of that commitment. It checks the stored record, not the working folder; `find` answers whether a current file was stamped.
- **`verify`** (online): runs `check` first, since a Bitcoin date means nothing if the record doesn't match, then checks the proof's block header through both explorers and prints the proven date. Its output reports the two parts separately. A pending stamp reports `Bitcoin: pending` and exits 0; run `upgrade` first to complete it.
- **`export` layout:** `<id>/README.txt`, `<id>/files/…` (the stamped folder structure, each file with its `.ots` beside it), and the original `snapshot.zip`, `receipt.json`, `proof.ots`.

## Output

Plain sentences, one result per line, no colors required. Examples:

```
$ draftstamp stamp -m "before submission"
Stamped 14 files of riemann-draft as 20261121T140312Z-e72b05.
Pending: Bitcoin confirmation usually takes a few hours. Run `draftstamp upgrade` later.

$ draftstamp log
20261121T140312Z-e72b05  riemann-draft  14 files  in Bitcoin block 921034  "before submission"
20261118T091500Z-a41c9e  riemann-draft  13 files  pending

$ draftstamp check e72b05
Record intact: all 14 files match the receipt, and the proof is for this stamp.

$ draftstamp verify e72b05
Record intact: all 14 files match the receipt, and the proof is for this stamp.
Bitcoin: confirmed in block 921034. These files existed by 2026-11-21 16:02 UTC.

$ draftstamp share chapters/chapter3.tex
Wrote chapter3.tex and chapter3.tex.ots.
Anyone can check it with: ots verify -f chapter3.tex chapter3.tex.ots
```

Status words: **pending** (calendar promise only); **in Bitcoin block N** (from the stored proof, offline: `log`, `find`); **confirmed in Bitcoin block N** (checked against the block header by `upgrade` or `verify`, with the block's date).

Exit codes: `0` success; `1` an error (bad input, I/O, network); `2` usage; `3` verification failed (a file, the receipt or the proof does not match). Errors go to stderr as one sentence.

## Network

- Blocking HTTP via `ureq`, implementing core's `Http`. 10-second timeout per request; core already runs calendar requests in parallel.
- `User-Agent: draftstamp/<version>`. No other identifying headers, no telemetry, no update checks.
- Only the hosts core and `opentimestamps-lite` choose are ever contacted.

## Core change

`Bundle::create` accepts a file as well as a folder (a one-file stamp, as above), and core exposes what the CLI needs: `Bundle::check` (offline), `Settings` and `default_project` (`.draftstamp`), `iso_time`, and `OtsError`. Spec `0001_core.md` is updated to match.

## Crate layout

```
crates/draftstamp-cli/
├── src/main.rs     parse arguments, build the real HTTP client, call run, set the exit code
├── src/lib.rs      run(args, http, env) -> exit code: every command, no global state
├── src/http.rs     ureq implementation of Http
└── tests/          commands end to end on temp folders and vaults with the simulated network
```

Dependencies: `draftstamp-core` (path), `clap` (derive), `ureq`.

## Tests

`run` takes the `Http`, the working directory, the vault path and output streams as parameters, so every command is tested in-process with core's simulated network: stamp, upgrade, log, find, check and verify (including a tampered bundle exiting with 3), share before and after upgrading, export, `init`, stamp references (prefix, suffix, ambiguous, default), and refusals to overwrite. No test contacts a real server.

## Open

- `--json` output for scripts and the desktop app.
- A `vault` key in `.draftstamp`, for per-project vaults.
- Shell completions and install packages (Homebrew, cargo install, release binaries).
