# draftstamp-core

Status: Draft · 2026-11-21

The DraftStamp engine. It turns a folder into a 32-byte commitment, timestamps it with `opentimestamps-lite`, and produces a bundle: the exact files, a receipt, and the proof. A vault stores bundles; history and search are built on top. The CLI and the desktop app are thin front ends over this crate.

## Interface

```rust
// One stamp: the snapshot, receipt and proof, and what can be done with it
impl Bundle {
    pub fn create(http: &impl Http, folder: &Path, opts: &StampOptions) -> Result<Bundle, Error>;
    pub fn upgrade(&mut self, http: &impl Http) -> Result<Status, Error>;
    pub fn verify(&self, http: &impl Http) -> Result<Verified, Error>;
    pub fn export(&self, out: &Path) -> Result<(), Error>;            // one zip for a reviewer, with verify.py
    pub fn id(&self) -> &StampId;
    pub fn receipt(&self) -> &Receipt;
    pub fn proof(&self) -> &Proof;
}

// Storage only: read and write bundles; no network, no logic
pub trait Vault {
    fn put(&self, bundle: &Bundle) -> Result<StampId, Error>;          // write a new bundle
    fn put_proof(&self, id: &StampId, proof: &Proof) -> Result<(), Error>; // the only change ever made: an upgraded proof
    fn get(&self, id: &StampId) -> Result<Bundle, Error>;
    fn receipt(&self, id: &StampId) -> Result<Receipt, Error>;         // without reading the snapshot
    fn proof(&self, id: &StampId) -> Result<Proof, Error>;             // without reading the snapshot
    fn list(&self) -> Result<Vec<StampId>, Error>;
}
pub struct LocalVault;                                                 // a folder on disk; LocalVault::open(root)

// Questions about stored stamps, over any Vault
pub fn history(vault: &impl Vault, project: Option<&str>) -> Result<Vec<StampInfo>, Error>;  // newest first
pub fn find(vault: &impl Vault, file: &Path) -> Result<Vec<Found>, Error>;                  // stamps containing these exact bytes

pub struct StampOptions { pub label: Option<String>, pub project: Option<String> }  // project defaults to the folder's name
pub struct StampInfo { pub id: StampId, pub project: Option<String>, pub label: Option<String>, pub files: usize, pub status: Status }
pub struct Found { pub stamp: StampInfo, pub path: String }            // path of the file inside that stamp
pub struct Verified { pub files: usize, pub status: Status }         // files re-hashed, proof checked
```

`Http`, `Status` and `Proof` come from `opentimestamps-lite`. Calls are blocking. `Bundle` does the work on one stamp and needs no vault; `Vault` only stores bundles and never touches the network; `history` and `find` read receipts and proofs through any `Vault`. Other storage (a git repository, remote encrypted storage) implements the same trait. The CLI's default vault is `~/DraftStamp`.

A front end composes them:

```rust
let vault = LocalVault::open(&root)?;
let id = vault.put(&Bundle::create(&http, folder, &opts)?)?;     // stamp
for id in vault.list()? {                                        // quiet upgrades
    let mut bundle = vault.get(&id)?;
    if let Status::Pending | Status::Claimed { .. } = bundle.proof().status() {
        bundle.upgrade(&http)?;
        vault.put_proof(&id, bundle.proof())?;
    }
}
```

## Bundle

```
<vault>/<stamp id>/
├── snapshot.zip     exactly the stamped files, at their canonical paths
├── receipt.json     file list and salts: turns the snapshot into the commitment
└── proof.ots        OpenTimestamps proof of the commitment
```

- **Stamp id** is the UTC time (`YYYYMMDDTHHMMSSZ`), a hyphen, and the first 6 hex characters of the commitment.
- `LocalVault::put` writes to a temporary folder and renames it into place, so a bundle is either complete or absent. `put_proof` rewrites only `proof.ots`, the same way, and refuses a proof whose digest is not the bundle's commitment. Proofs only ever gain attestations, because `opentimestamps-lite` upgrades only add.
- All three files are needed to prove anything; each bundle folder verifies on its own, anywhere.
- **Project** is an optional tag recorded in the receipt, defaulting to the stamped folder's name. It only groups stamps for `history(vault, Some(project))`; the layout stays flat and nothing depends on it.

## Commitment

**File selection.** Every regular file under the folder being stamped. Skipped: symlinks, empty folders, and anything inside `.git`, `.draftstamp` or `__MACOSX`, or named `.DS_Store`, `Thumbs.db` or `desktop.ini`. An empty selection is an error.

**Canonical paths.** Relative to the stamped folder, `/` separators, Unicode NFC, UTF-8, case preserved, at most 4096 bytes. No empty, `.` or `..` segments, backslashes or NUL. Two files that collide after NFC are an error. Leaves are sorted by the paths' UTF-8 bytes.

**Hashing.**

```
file_hash   = SHA256(file bytes)
leaf_hash   = SHA256(0x00 ‖ salt[16] ‖ u32be(len(path)) ‖ path ‖ file_hash)
node_hash   = SHA256(0x01 ‖ left ‖ right)
root        = RFC 6962 Merkle Tree Hash of the leaf hashes (split at the largest power of two below n)
commitment  = SHA256(0x02 ‖ "draftstamp:v1" ‖ root)
```

`salt` is 16 random bytes, fresh per file per stamp, so sharing one file's proof never lets anyone test guesses about the others. The prefixes keep leaves, nodes and commitments from being confused. The commitment is what `opentimestamps-lite` stamps.

## Receipt

```json
{
  "format": "draftstamp.receipt",
  "version": 1,
  "committed": {
    "tree": "draftstamp-merkle-v1",
    "leaves": [ { "path": "main.tex", "size": 48213, "sha256": "9f86d0…", "salt": "b3c1e0…" } ],
    "root": "a3f9c1…",
    "commitment": "e72b05…"
  },
  "advisory": {
    "id": "20261121T140312Z-e72b05",
    "createdAt": "2026-11-21T14:03:12Z",
    "project": "riemann-draft",
    "label": "Section 3 rewrite"
  }
}
```

- `committed` is what the proof covers. Readers recompute `root` and `commitment` from the leaves and reject any mismatch, unknown field, unknown version or unsorted leaf. Hashes and salts are lowercase hex.
- `advisory` is for people and tools; it is never used to decide validity, and unknown advisory fields are ignored.
- Status is never stored; it comes from `proof.ots`.
- The receipt is private: with it, anyone holding a guess about a file can check it.

## Verification

1. Parse the receipt.
2. Re-hash every file in the snapshot and match it to its leaf.
3. Recompute the root and commitment; both must match the receipt.
4. Check `proof.digest()` equals the commitment.
5. Upgrade the proof if pending and check it against Bitcoin (`opentimestamps-lite`).

Steps 1–4 need no network. A bundle also verifies without DraftStamp: `tools/verify.py` (Python standard library only) runs steps 1–4 on a stamp folder or an exported zip, and the official `ots verify -d <commitment> proof.ots` runs step 5.

## Rules

- Nothing about the work leaves the machine except the blinded digest `opentimestamps-lite` sends to the calendars.
- The vault only adds: there is no delete or overwrite; `put_proof` is the single permitted change.
- `find` matches exact bytes (by SHA-256), across every stamp in the vault.
- Front ends upgrade pending bundles before other commands; network failures never block them.

## Layout

```
crates/draftstamp-core/src/
├── lib.rs
├── error.rs
├── id.rs         stamp ids and UTC times
├── commitment/   paths.rs (selection, canonical paths) · tree.rs (hashing) · receipt.rs
├── bundle.rs     Bundle: create, upgrade, verify, export
├── vault.rs      the Vault trait and LocalVault
└── query.rs      history, find
```

Dependencies: `opentimestamps-lite`, `sha2`, `getrandom`, `serde`, `serde_json`, `unicode-normalization`, `zip`.

## Tests

All offline. Commitment test vectors come from an independent stdlib-only Python implementation of this spec (`spec/vectors/gen_0001.py`, output in `spec/vectors/0001.json`). `Bundle` tests use a recorded-reply `Http`: create, upgrade, verify, export, and tampered bundles (an edited file, receipt or proof must fail). `LocalVault` tests run in temporary folders with no network: put, get, list, `put_proof` rules, interrupted writes. Query tests run `history` and `find` over stored bundles. A cross-check runs `tools/verify.py` against bundles and exports written by the crate.
