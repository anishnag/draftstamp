Wrote chapter3.tex and chapter3.tex.ots from stamp 20261121T140312Z-e72b05.
— the recipient, with the official OpenTimestamps client —$ ots verify -f chapter3.tex chapter3.tex.ots
Success! Bitcoin block 976886 attests existence as of 2026-11-21 UTC

How it works

DraftStamp builds on OpenTimestamps, the open standard for timestamping in Bitcoin. It adds what ongoing work needs: whole folders as one record, the exact files kept with each proof, and private sharing.

Your files→Salted Merkle tree→One 32-byte commitment→OpenTimestamps calendars→A Bitcoin block
1

Stamp

Point it at a folder or a file. Each file's contents and path are committed, with a random salt per file, into one value sent to the free public calendars.

2

Keep

The exact files, a receipt and the proof are stored together in a local vault. Once Bitcoin confirms (usually a few hours), upgrade completes the proof.

3

Share

Any file, folder or selection can be shared, each file with its own standard .ots. Salts keep the files you didn't share hidden.

Anyone can check it, without us

Every shared file comes with an ordinary OpenTimestamps proof. The person you send it to runs the official client, or uses any other implementation. DraftStamp isn't involved.

  • Standard proofs. Each file's .ots is checked with ots verify -f, exactly like any OpenTimestamps proof.
  • Private by design. The calendars see one random-looking 32-byte value. A shared file reveals itself, not the others.
  • Built to last. A confirmed proof needs only Bitcoin's block headers. No company has to stay in business.
  • Open formats. Everything is specified, with test vectors from an independent implementation.

Questions

Do I need Bitcoin or a wallet?

No. The OpenTimestamps calendars are free public services that batch everyone's timestamps into Bitcoin transactions they pay for.

What exactly does a stamp prove?

That these exact bytes existed by the time of a Bitcoin block, give or take a couple of hours. It shows possession at a time, not authorship.

How is this different from running ots stamp?

DraftStamp's proofs work with the official client. It adds the workflow around them: whole folders as one record with each file's path bound in, the exact files kept with each proof, project history, and private sharing of any file or folder.

What if I lose my vault?

You lose the proofs you hadn't shared or exported, since a proof is only useful next to the exact files. Keep ~/.dsvault in your backups.
